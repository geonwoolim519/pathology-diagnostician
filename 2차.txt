# 병리진단의사 — 케이스 잠금 제거 및 신규 질환 확장 프롬프트

## 1. 프로젝트 목표

기존에 개발한 React 기반 교육용 웹앱 **「병리진단의사(Pathology Diagnostician)」**를 개선한다.

이번 작업의 핵심 목표는 다음과 같다.

1. 모든 케이스의 잠금 기능을 완전히 제거한다.
2. 기존 30개 질환 케이스를 삭제하거나 변경하지 않는다.
3. 기존 케이스와 중복되지 않는 새로운 질환 케이스 30개를 추가한다.
4. 총 60개 이상의 질환 케이스를 제공한다.
5. 계통별 검색, 필터링, 난이도 선택을 개선한다.
6. 간호학과 2학년 수준에 맞는 병리학 교육 콘텐츠를 제공한다.
7. 기존 학습 기록, 점수, 오답노트 기능을 유지한다.

**중요:** 처음부터 프로젝트를 새로 만들지 말고 현재 프로젝트의 구조와 컴포넌트, 데이터 파일을 먼저 확인한 뒤 기존 코드에 필요한 변경 사항만 적용한다.

---

## 2. 케이스 잠금 시스템 완전 제거

현재 앱에 케이스 순차 잠금, 레벨 잠금 또는 일정 개수의 케이스를 완료해야 다음 케이스가 열리는 기능이 있다면 모두 제거한다.

### 제거할 기능

- 첫 5개 케이스만 이용할 수 있도록 제한하는 기능
- 특정 케이스를 완료해야 다음 케이스가 열리는 기능
- 10개 완료 후 보통 난이도를 해제하는 기능
- 20개 완료 후 어려운 난이도를 해제하는 기능
- 케이스 카드에 자물쇠 아이콘을 표시하는 기능
- 잠긴 케이스를 클릭할 수 없도록 만드는 기능
- 특정 레벨이나 학습 진도에 따라 접근을 제한하는 조건문
- 잠금 해제를 위한 별도의 점수 및 진행 조건

관련 코드가 여러 컴포넌트에 분산되어 있다면 모두 확인하여 제거한다.

### 변경 후 동작

모든 사용자는 처음부터 모든 케이스를 자유롭게 선택할 수 있어야 한다.

예를 들어 사용자는 다음과 같이 학습할 수 있어야 한다.

- CASE 01부터 순서대로 학습
- CASE 17부터 바로 학습
- 가장 어려운 케이스부터 도전
- 신경계 질환만 선택하여 학습
- 이전에 틀린 케이스만 다시 풀기
- 완료한 케이스를 반복해서 풀기

**난이도는 접근 권한이 아니라 학습 정보로만 사용한다.**

케이스 카드에는 자물쇠 대신 다음 상태를 표시한다.

- 미풀이
- 완료
- 정답
- 오답 경험 있음

이 상태는 학습 기록을 위한 것이며 접근을 제한해서는 안 된다.

## 3. 기존 데이터 보존

현재 존재하는 30개 케이스는 그대로 유지한다.

기존 케이스의 ID, 질환명, 해설, 정답, 병태생리 및 간호학적 포인트를 임의로 삭제하거나 변경하지 않는다.

기존 데이터 파일이 `src/data/cases.ts`라면 해당 파일의 구조를 확인하고 신규 데이터를 같은 형식으로 추가한다.

가능하면 다음과 같이 데이터를 분리한다.

- `src/data/cases.ts` — 기존 30개 케이스
- `src/data/additionalCases.ts` — 신규 케이스
- `src/data/pathologyTerms.ts` — 병리학 용어
- `src/data/pathologyLessons.ts` — 병리학 학습 자료

실제 프로젝트의 구조가 다르다면 기존 구조를 존중하면서 가장 적절한 방식으로 적용한다.

전체 케이스 목록에서는 기존 데이터와 신규 데이터를 합쳐 표시한다.

```ts
const allCases = [...originalCases, ...additionalCases];
```

위 코드는 개념 예시다. 실제 변수명은 기존 프로젝트에 맞춰 적용한다.

ID는 기존 케이스와 겹치지 않도록 고유하게 지정한다.

## 4. 신규 질환 케이스 30개

아래 30개를 신규 케이스로 추가한다. 기존 30개와 질환이 중복되지 않도록 한다.

기존 질환과 병태생리가 비슷하더라도 새로운 질환을 독립적인 학습 목표로 삼을 수 있다면 추가할 수 있다. 다만 단순히 증상이나 환자 나이만 바꾼 복제 케이스는 만들지 않는다.

### A. 신경계

**CASE 31. 허혈성 뇌졸중**

- 핵심 병태생리: 뇌혈관 폐색, 뇌조직 허혈 및 세포 손상
- 주요 단서: 갑작스러운 편측 위약, 언어장애
- 학습 목표: 허혈과 뇌조직 손상의 관계 이해

**CASE 32. 알츠하이머병**

- 핵심 병태생리: 진행성 신경세포 손상과 신경퇴행
- 주요 단서: 점진적인 기억력 및 인지기능 저하
- 학습 목표: 신경퇴행성 질환의 특징 이해

**CASE 33. 파킨슨병**

- 핵심 병태생리: 흑질의 도파민 신경세포 소실
- 주요 단서: 안정 시 떨림, 운동완만, 근육 경직
- 학습 목표: 신경전달물질 변화와 운동 증상 연결

**CASE 34. 다발성경화증**

- 핵심 병태생리: 중추신경계의 탈수초성 손상
- 주요 단서: 시각장애, 감각 이상, 신경학적 증상의 반복
- 학습 목표: 수초 손상이 신경전도에 미치는 영향 이해

### B. 내분비계 및 대사 질환

**CASE 35. 제1형 당뇨병**

- 핵심 병태생리: 췌장 베타세포의 자가면역성 파괴
- 주요 단서: 다뇨, 다음, 체중 감소, 고혈당
- 학습 목표: 인슐린 결핍과 혈당 상승의 관계 이해

**CASE 36. 제2형 당뇨병**

- 핵심 병태생리: 인슐린 저항성과 진행성 베타세포 기능 저하
- 주요 단서: 고혈당, 인슐린 저항성 위험요인
- 학습 목표: 인슐린 작용 장애와 대사 이상 이해

**CASE 37. 그레이브스병**

- 핵심 병태생리: 갑상샘 자극 수용체에 대한 자가항체
- 주요 단서: 갑상샘기능항진, 빈맥, 체중 감소, 안구 돌출 가능성
- 학습 목표: 자가면역과 호르몬 과다의 관계 이해

**CASE 38. 하시모토 갑상샘염**

- 핵심 병태생리: 자가면역성 갑상샘 손상
- 주요 단서: 갑상샘기능저하, 피로, 추위 민감성
- 학습 목표: 만성 염증과 내분비 기능 저하 이해

**CASE 39. 쿠싱증후군**

- 핵심 병태생리: 만성적인 코르티솔 과다
- 주요 단서: 중심성 비만, 근위부 근력 저하, 고혈압 가능성
- 학습 목표: 호르몬 과다에 따른 전신 변화 이해

### C. 감염성 및 면역 질환

**CASE 40. 패혈증**

- 핵심 병태생리: 감염에 대한 조절되지 않는 숙주 반응과 장기 기능 장애
- 주요 단서: 감염 의심, 의식 변화, 저혈압 또는 장기 기능 이상
- 학습 목표: 감염과 전신 염증 반응의 차이 이해

**CASE 41. 세균성 수막염**

- 핵심 병태생리: 바이러스 감염과 간세포 손상
- 주요 단서: 간효소 상승, 피로, 황달 가능성

**CASE 43. 전신홍반루푸스**

- 핵심 병태생리: 자가항체와 면역복합체에 의한 다기관 손상
- 주요 단서: 피부 발진, 관절 증상, 신장 침범 가능성
- 학습 목표: 자가면역 질환의 전신적 특성 이해

- 핵심 병태생리: 면역 매개 염증과 표피세포의 과도한 증식

- 핵심 병태생리: 심장의 펌프 기능 저하 또는 충만 이상

## 5. 모든 신규 케이스의 상세 데이터 작성

위 목록은 질환과 핵심 학습 목표를 지정한 것이며, 실제 앱에서는 각 케이스에 충분한 교육용 콘텐츠를 작성한다.

각 케이스는 다음 필드를 포함한다.

- `id`
- `title`
- `system`
- `difficulty`
- `patient`
- `chiefComplaint`
- `history`
- `physicalExamination`
- `tests`
- `pathologyFindings`
- `clues`
- `options`
- `answer`
- `explanation`
- `pathophysiology`
- `nursingPoints`
- `hints`
- `keyTerms`
- `differentialDiagnosis`
- `references`

### 작성 기준

1. 환자는 모두 가상의 인물로 작성한다.
2. 증상, 검사 결과 및 병리소견은 서로 모순되지 않도록 한다.
3. 정답은 각 케이스에서 하나로 명확하게 정할 수 있도록 구성한다.
4. 오답 선택지는 실제로 혼동할 수 있는 질환으로 구성한다.
5. 정답 해설에서는 핵심 단서와 다른 선택지를 구별하는 근거를 설명한다.
6. 병태생리는 간호학과 2학년이 이해할 수 있는 수준으로 설명한다.
7. 간호학적 포인트는 관찰, 사정, 위험 징후 인지, 환자 교육 중심으로 작성한다.
8. 진단 및 치료를 지나치게 전문적인 수준으로 확장하지 않는다.
9. 실제 검사 수치를 사용할 때는 단위와 참고범위를 함께 표시하고, 기관별 차이가 있을 수 있음을 안내한다.
10. 실제 병리 이미지가 없는 경우 이미지를 만들어낸 것처럼 표현하지 않는다. 교육용 도식과 설명을 사용한다.

특히 CASE 31~60의 모든 질환은 제목만 추가하는 것으로 끝내지 말고 실제 풀이가 가능한 완성된 데이터로 작성한다.

## 6. 계통별 필터 확장

기존 계통 필터에 신규 계통을 추가한다.

- 전체
- 소화기계
- 호흡기계
- 심혈관계
- 비뇨기계
- 생식기계
- 혈액계
- 신경계
- 내분비계
- 면역계
- 감염성 질환
- 피부계
- 근골격계
- 대사성 질환

한 질환이 여러 계통에 해당한다면 데이터 구조에 보조 태그를 추가할 수 있다.

검색창에서는 질환명, 주요 증상, 병리 용어 및 계통을 검색할 수 있도록 한다.

## 7. 케이스 목록 UI 개선

전체 케이스 화면 상단에 다음 정보를 표시한다.

- 전체 케이스 수
- 완료한 케이스 수
- 미풀이 케이스 수
- 오답 경험이 있는 케이스 수

케이스 카드에는 다음 정보를 표시한다.

- 케이스 번호
- 질환명 또는 학습 모드에 따른 제목
- 계통
- 난이도
- 완료 상태
- 핵심 학습 주제

기존의 자물쇠 아이콘과 잠금 안내 문구는 모두 제거한다.

**완료 여부와 관계없이 모든 카드는 언제나 클릭할 수 있어야 한다.**

난이도별 필터를 선택해도 해당 난이도에 속한 모든 케이스에 접근할 수 있어야 한다.

## 8. 학습 기록과 오답노트 유지

기존 점수와 학습 기록 기능은 유지한다.

신규 케이스에서도 동일하게 동작하도록 한다.

- 정답률
- 케이스별 최고 점수
- 최근 풀이 날짜
- 오답 기록
- 사용한 힌트 수
- 다시 풀기
- 계통별 정답률

케이스 ID를 기준으로 기록을 관리한다.

기존 30개 케이스의 기록이 신규 데이터 추가로 초기화되거나 다른 케이스에 연결되지 않도록 한다.

기존 저장 방식이 localStorage라면 기존 키와 데이터 형식을 먼저 확인한다. 필요한 경우 하위 호환성을 유지하는 마이그레이션을 구현한다.

## 9. 난이도 시스템

난이도는 다음 세 단계로 유지한다.

### 쉬움

주요 병리학적 특징을 파악하면 해결할 수 있는 케이스.

### 보통

임상 증상, 검사 결과 및 병리소견을 종합해야 하는 케이스.

### 어려움

유사 질환 간 차이를 비교하고 핵심 병리소견을 해석해야 하는 케이스.

난이도 분류는 학습 안내 목적으로만 사용한다.

어려움 등급이라도 사용자가 처음부터 바로 풀 수 있어야 한다.

---

## 10. 병리학 교육의 정확성

교육용 콘텐츠를 작성할 때 다음 원칙을 지킨다.

- 질환의 원인, 병태생리, 주요 조직 변화 및 임상 증상을 구분한다.
- 모든 질환이 반드시 조직검사로 진단되는 것처럼 표현하지 않는다.
- 임상 진단과 병리학적 진단의 차이를 설명한다.
- 검사 하나만으로 확진할 수 없는 질환은 필요한 추가 정보가 있음을 설명한다.
- 감별진단의 근거를 명확하게 제시한다.
- 실제 의학적 사실과 단순화한 교육용 사례를 구분한다.
- 검증되지 않은 논문이나 참고문헌을 만들어내지 않는다.
- 질환별 참고자료가 확실하지 않으면 신뢰할 수 있는 교과서 또는 공식 보건의료기관의 자료를 확인하도록 표시한다.

교육용 사례는 질환의 전형적인 특징을 학습하도록 단순화할 수 있지만, 단순화한 내용을 실제 임상에서 항상 성립하는 규칙처럼 표현하지 않는다.

## 12. 구현 및 테스트 순서

다음 순서로 실제 프로젝트에 적용한다.

1. 현재 프로젝트의 데이터 구조와 라우팅을 확인한다.
2. 모든 케이스 잠금 조건과 잠금 UI를 검색한다.
3. 잠금 로직을 제거한다.
4. 기존 30개 케이스와 학습 기록이 정상적으로 유지되는지 확인한다.
5. 신규 질환 30개를 데이터 파일에 추가한다.
6. 전체 케이스 목록을 60개 이상으로 통합한다.
7. 계통별 필터와 검색을 확장한다.
8. 점수, 힌트, 오답노트가 신규 케이스에서도 동작하도록 한다.
9. 각 케이스의 정답과 해설이 일치하는지 검사한다.
10. 모바일과 데스크톱에서 UI를 점검한다.
11. TypeScript 오류와 빌드 오류를 수정한다.
12. 최종적으로 모든 케이스를 처음부터 선택할 수 있는지 확인한다.

### 최종 완료 조건

- 기존 케이스 30개 유지
- 신규 질환 케이스 30개 추가
- 총 60개 이상의 케이스
- 모든 케이스 자유 선택 가능
- 잠금 아이콘 및 잠금 로직 완전 제거
- 기존 학습 기록 유지
- 신규 케이스의 정답·힌트·해설 작동
- 계통별 검색과 필터 작동
- 오답노트 및 반복 학습 작동
- 모바일 반응형 지원
- 오류 없는 빌드

기존 프로젝트를 최대한 재사용하면서 위 요구사항을 구현한다. 변경 후에는 실제로 수정한 파일과 구현 결과, 테스트 결과를 간단하게 보고한다.
